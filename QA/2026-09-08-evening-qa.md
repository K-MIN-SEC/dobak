# 0908 브랜치 저녁 QA

## 조건과 검증 방식

- 일시: 2026-09-08, 19:41 시작, 20:00 마감(KST).
- Unity 6000.4.0f1의 TabletUI 씬을 실제 Play 모드로 실행했다. Game 뷰 16:10에서 화면을 읽고 마우스로 클릭했다.
- 게임 코드, CSV, 씬을 수정하지 않았다. 진행을 막는 오류를 만나지 않아 예외 수정도 하지 않았다.
- 기존에 변경되어 있던 `Assets/Editor/ScenarioV4FullPlayQa.cs`는 건드리지 않았다. 이 자동 QA의 내부 함수 호출이나 강제 상태 변경은 이번 검증에 사용하지 않았다.
- 아래의 '실제 확인'은 에디터 UI 조작으로 관찰한 결과이고, '정적 검토'는 파일에서 확인한 위험이다. 둘을 동일한 통과/실패 결과로 취급하지 않는다.
- 이번 QA는 전체 루트 완료가 아니다. 실제 진행 범위는 첫날 정상 등교, 메시지, 공부 오답/정답, 첫 도박 성공 후 중단, 취침, 둘째 날 아침까지다.

## 실제 조작 기록

1. Play 실행 후 1일차 07:00 기상 장면이 표시됐다. 노트북 파손, 수리비 25만 원, 잔액 15만 원, 주말 이틀 근무로 10만 원을 모으는 설명을 순서대로 읽었다.
2. 안내를 닫고 지도 아이콘과 학교 아이콘을 클릭했다. 학교 배경 및 16:00 수업/조별과제 대사에 진입했다.
3. 선생님 발표 주제 → 서연 역할 분담 → 주인공 질문 → 출처 확인 → 서연 작별 → 주인공 '월요일에 보자'까지 확인했다.
4. 학교 위치의 태블릿에서 엄마 메시지가 수신됐다. 메시지 앱 → 엄마 방 → 답장 선택을 클릭했다. 주인공 말풍선 1개, '입력중...' 후 엄마 후속 말풍선을 확인했다.
5. 하단 뒤로 가기를 눌렀다. 학교 배경에서 '(종례도 끝났다. 집에 가서 남은 일정을 확인하자.)'가 먼저 나왔다. 다음 탭 후 집 위치와 민재 수신 안내가 표시됐다. 짧은 페이드의 전 프레임은 녹화하지 않았으므로 전환 중 깜빡임 부재까지 인증하지 않는다.
6. 메시지 앱을 열자 최근 대화인 민재 방이 표시됐다. 첫 수신 → 주인공 독백 → 가입 보너스/수익 권유 → 주인공 갈등 → 링크 수신 → 답장 버튼 순으로 확인했다.
7. 답장 버튼을 눌러 '링크는 받았어. 오늘 할 일부터 보고 내가 정할게.'가 한 번 전송됐다. 직접 상태를 강제로 완료시키지 않았다.
8. 채팅을 닫고 공부 전 도박 아이콘을 눌렀다. '(아직 오늘 해야 할 일이 남아 있다. 공부부터 끝내자.)'로 차단됐다.
9. 공부 앱에서 오답 B를 선택 → 피드백 → 다시 문제 → 정답 A → 피드백 → 공부 완료를 확인했다. 시간은 16:00에서 18:00으로 진행했다.
10. 저녁 장면과 21:00 밤 배경, 취침/도박 선택 안내를 확인했다.
11. 도박 아이콘 → '한다'를 클릭했다. 22:00, 첫 성공 20,000원 입금 대사 및 후속 갈등 대사가 나왔다.
12. '여기서 멈춘다' → 중단 독백 → 태블릿 잔액 170,000원 → 취침 앱 → 취침하기를 클릭했다.
13. 2일차 토요일 07:00 기상 장면과 잘못된 남은 수리비 문장을 직접 확인했다.

## 실제 확인한 문제와 해결안

### E01. 도박 수익 이후에도 둘째 날 남은 수리비가 5만 원으로 고정됨

- 분류: 금액/맥락 오류, 진행 가능.
- 재현: 첫날 150,000원 → 첫 도박 성공 +20,000원 → 중단/취침 → 둘째 날 아침.
- 실제 문장: '오늘 일당 5만 원을 받으면 수리비까지 5만 원만 남는다.'
- 기대: 현재 170,000원 + 일당 50,000원 = 220,000원, 목표까지 30,000원. 손실이나 목표 초과가 있으면 그에 맞는 표현이 필요하다.
- 원인: `Assets/Resources/ScenarioV5.csv`, `v5_d2_start_02`에 잔액 조건 없이 고정 문장이 들어 있다. 실제 출력도 동일하다.
- 해결안: 현재 잔액/목표로 부족분을 계산하거나, 금액을 단정하지 않는 문장으로 바꾼다. 목표 달성 상태와 손실 상태도 분리한다. 생성 원본 `Tools/BuildScenarioV5.ps1`을 함께 정리해야 재생성 때 되돌아가지 않는다.
- 재검증: 첫날 미도박, 1회 성공, 2회 성공, 손실, 차용 후 기상 각각 대사와 은행 잔액을 대조한다.

### E02. 귀가해서 두 시간 공부한 뒤 다시 귀가 인사를 받음

- 분류: 장면 맥락 오류, 진행 가능.
- 재현: 첫날 16:00 집 도착 → 민재 대화 완료 → 집에서 공부 완료 → 18:00 저녁 장면.
- 실제 문장: 엄마 '왔어? 손 씻고 밥부터 먹자', 주인공 '응. 금방 갈게.'
- 기대: 이미 집에 머물렀으므로 '공부 끝났어? 밥 먹자' 같은 저녁 호출이 자연스럽다.
- 원인: `ScenarioV3FinalRuntimeFix.cs`의 `PatchD8EveningTiming()`이 모든 `evening_fill` 장면에 엄마 대사를 삽입한다. 집에 있었는지는 실제 체류 상태가 아니라 장면 ID의 `missed` 포함 여부로 나눈다. 따라서 정상 귀가 후 공부한 경우도 귀가 인사로 처리된다.
- 해결안: 귀가 인사는 실제 귀가 시점에만 사용하고, 저녁 채우기 장면은 이미 집에 있는 상태의 대사를 사용한다. 새 분기/우회 전환을 더하기보다 해당 패치의 대사 선택 조건을 좁힌다.
- 재검증: 공부 후, 근무 후, 결근 후, 늦은 귀가 후 저녁을 각각 확인한다. 저녁 시간 설정과 취침 유도는 유지한다.

### E03. 주인공 독백 괄호가 일부 화면에서 빠짐

- 분류: 문체/표시 규칙 불일치, 진행 가능.
- 실제 확인: 공부 정답 및 오답 피드백은 화자가 '나'인데 괄호가 없다. 첫날 저녁 '오늘은 여기까지 하자. 내일 알바도 있으니까...'에도 괄호가 없다. 앞뒤 독백은 괄호가 있다.
- 원인 1: `QuizManager.cs:529,538`이 `V3ShowDialogue("나", ...)`로 원문을 넘겨 Director의 독백 포맷을 거치지 않는다.
- 원인 2: `ScenarioV3Director.cs:1933`의 `IsProtagonistMonologue()`는 dialogue 행을 장면 전체에 다른 등장인물이 있는지로 판정한다. E02의 엄마 대사 삽입이 저녁 독백 판정에도 영향을 준다.
- 해결안: 화자 이름만으로 모든 말을 괄호 처리하지 말고, 독백 여부를 행 단위로 명시한다. 공부 피드백은 독백 표시 경로를 쓰고, 실제 상대에게 한 답변은 그대로 둔다.
- 재검증: 학교에서 말하는 대사, 혼잣말, 공부 피드백, 엄마에게 답하는 말, 메시지 말풍선을 함께 확인한다.

### E04. 첫 학교 장면에서 상담 자료로 넘어가는 설명이 부족함

- 분류: 처음 플레이하는 사람 관점의 맥락 개선 필요, 진행 가능.
- 실제 순서: 선생님 '온라인 광고랑 확률 표현' → 서연 '상담 번호랑 사례', '예방치유원 자료'. 무엇에 관한 상담인지, 왜 해당 기관 자료가 필요한지 설명이 없다.
- 원인: `d1_school_01`과 `d1_school_05` 사이의 주제 연결 문장이 압축 과정에서 부족해졌다.
- 해결안: 발표 대상으로 '온라인 도박 광고'를 선택했다는 짧은 연결과 상담 자료의 목적을 한 문장으로 명확히 한다. 기관명만 아는 개발자 관점의 설명은 피한다.

### E05. 민재 답장 버튼에 보낼 내용이 보이지 않음

- 분류: 조작/표현 개선 필요, 진행 가능.
- 실제: 엄마 답장은 보낼 문장이 버튼에 나오지만, 민재 마지막 답장은 빈 입력란 위에 '메시지 보낸다.'만 보인다. 클릭해야 실제 내용이 드러난다.
- 기대: 플레이어가 보내기 전에 주인공이 무슨 말을 할지 알 수 있어야 한다.
- 원인 범위: 자동 발신 대기 UI와 명시적 선택지 답장 UI의 라벨/미리보기 방식이 다르다. 이번 시간에는 해당 생성 함수까지 원인을 확정하지 않았다.
- 해결안: 대기 중 발신 내용을 입력란이나 버튼에 미리 보여주되, 실제 전송은 현행 클릭 시 한 번만 실행한다. 다른 인물 자동 답장도 같은 규칙으로 검토한다.

## 파일에서 확인한 추가 위험: 실제 재현 미완료

### S01. 빚을 지지 않은 고위험 루트에 빚 관련 대사가 나올 수 있음

- `v5_d4_start_risk_01`: 조건은 도박 3회 이상과 정상 기상뿐인데 '잃은 돈과 빌린 돈'이라고 한다.
- `v5_d4_help_response_01`: 도움 요청 시 '혼자 갚으려고'라고 한다. 손실만 있고 차용하지 않은 경우를 구분할 필요가 있다.
- `ending_no_help_01`: '빚과 놓친 일정을 더 크게 만들었다'가 고정이다. 해당 엔딩 진입 조건은 도박 횟수/도움 여부 중심이다.
- 제안: 현재 부채와 실제 차용 이력, 일정 실패 상태를 기준으로 문장을 나누고, 단순 손실을 부채로 표현하지 않는다. 이 엔딩까지 실제 플레이로 재현한 것은 아니다.

### S02. 발표 완료 칭찬의 조건이 과제 완료 여부를 확인하지 않음

- `v5_d5_school_prevented`, `v5_d5_school_recovery`는 도박 횟수/도움 요청 조건으로 나뉘지만 과제 미완료 여부가 문장 조건에 없다.
- '자료까지 끝냈잖아', '네 역할은 마무리했네'가 실제 과제 누락 루트에서도 가능한지 확인해야 한다.
- 제안: 먼저 4일차 과제를 미완료로 다음날에 갈 수 있는 정상 조작 경로가 있는지 확인한다. 가능하면 제출 상태에 따른 발표 대체 문장을 연결한다. 진입 불가능한 상태를 실제 버그로 단정하지 않는다.

### S03. 4일차 공부가 전제로 하는 사례 설명 부족

- 공부 자료는 '오늘 학교에서 다룬 사례'와 손실 만회를 위한 차용을 묻는다.
- 안정 학교 루트는 무료 포인트/보상 유혹 설명이 중심이며, 구체적인 차용 사례를 직접 소개하지 않는다.
- 제안: 공통 수업에 짧은 사례를 두거나 문제 문구를 독립적으로 이해할 수 있게 한다. 위험 루트만 보고 통과시키지 않는다.

## 미확인 항목

- 2일차 카페 근무부터 5일차 모든 엔딩까지 실제 UI 완주.
- 미도박 전체 루트, 2회 이득 후 중단, 고위험 무차용, 엄마/서준/민재 차용, 반복 거절, 재차용 제안.
- 21:59와 22:00 경계의 즉시/다음날 차용, 아침 장면 후 차용 선택 표시, 주말/평일 및 마지막 날 경계.
- 밤샘 강제 기상, 지각 지도 독백, 근무/메시지 미처리 상태 도박 차단.
- 16:9, Android 태블릿 및 WebGL 빌드의 실제 입력. 이번 에디터 성공을 웹 성공으로 간주하지 않는다.
- 연속 도박 시 홈으로 빠지는 문제, 메시지 중간 이탈/재진입, 장문 스크롤, 상태바 알림 삭제의 전체 조합.

## 결론

직접 확인한 범위에서 진행 중단은 없었지만, 대사와 상태가 어긋나는 문제가 남아 있다. 전체 루트 QA 완료나 무버그 판정은 할 수 없다. 코드 수정 없이 관찰 결과와 해결안을 남겼다.
